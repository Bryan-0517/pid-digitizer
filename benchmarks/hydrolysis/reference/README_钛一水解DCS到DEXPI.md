# 钛一水解DCS → DEXPI 预备包（初版）

## 1. 这是什么
本包把以下来源整理为结构化台账：
- 9张水解及后处理DCS画面：晶种、水解、水解二、冷却器、一洗、漂白、二洗、盐处理、树脂净化；
- 《水解AI实施要点》；
- 设备节点、工艺连接、仪表候选、操作阶段、关键控制点、AI变量和待核实问题。

它的定位是 **“DCS截图 → 可核对的结构化底稿（pre-DEXPI）”**，不是正式P&ID，也不是可直接投用的DEXPI XML。

## 2. 最先用哪个文件
先打开：
- `钛一_水解DCS流程数字化_初版.xlsx`

建议核对顺序：
1. `01_DCS画面`：确认截图归属区域和画面名称；
2. `02_设备节点`：确认设备Tag、中文名称、设备类型和系统归属；
3. `03_工艺连接`：确认“从哪里到哪里”、介质、跨画面连接；
4. `04_仪表控制`：确认温度、流量、液位、压力、阀门Tag与设备关系；
5. `05_AI变量`与`06_操作阶段`：核对水解AI变量是否能从DCS/LIMS/人工记录获得；
6. `09_待核实`：优先处理P0事项；
7. `10_DEXPI缺口`：收集正式P&ID、Line List、阀门表、仪表Index、I/O表等后，才进入DEXPI建模。

## 3. 本包主要文件
- `钛一_水解DCS流程数字化_初版.xlsx`：人工核对、开会和分工用的主台账；
- `钛一_水解DCS流程图_初步结构化.json`：程序可读的结构化底稿；
- `shuijie_dcs_tabular_export/*.csv`：分表导出，便于交给数据/建模团队；
- `validate_shuijie_dcs_graph.py`：检查JSON的Tag、节点、连接和仪表引用；
- `source_manifest.txt`：截图目录。

## 4. 现场核对方式
- 工艺：核对物料流向、跨区接口、工艺阶段、标准条件；
- 设备：核对设备Tag、实际名称、容积、泵/槽/换热器类型；
- 仪表：核对DCS点名、仪表量程、报警、阀门、回路和联锁；
- AI/数据：确认历史库Tag、采样频率、批次ID、LIMS样品ID及沉降高度/水解率等标签。

状态建议：
- `已确认`：经现场、台账或正式P&ID核实；
- `待现场核实`：仅依据截图或AI资料提取；
- `待补资料`：需P&ID、SOP、点表、控制逻辑等材料。

## 5. 当前不能直接出正式DEXPI的原因
截图没有完整给出管线号、管径、材质等级、喷嘴、阀门失效位、完整仪表回路、报警联锁、安全阀与放空等关键工程属性。
因此，在`09_待核实`中的P0事项关闭前，禁止将本包直接作为工程设计或安全操作依据。

## 6. JSON检查与CSV重新导出
在Python环境中运行：
```bash
python validate_shuijie_dcs_graph.py
```
脚本会输出：
- 重复Tag提醒；
- 连接引用不存在节点；
- 仪表归属不存在节点；
- 重新导出的CSV目录。

## 7. 数据安全与使用边界
本包基于现场HMI照片，可能包含读取误差或时间截面状态。任何DCS设定、阀位、联锁、报警或现场操作，应以现行SOP、正式P&ID、控制逻辑和授权人员判断为准。
